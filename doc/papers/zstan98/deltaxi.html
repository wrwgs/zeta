Proposal for the Z Standard, by Wolfgang Grieskamp (wg@cs.tu-berlin.de), November 11, 1998, (v3) , postscript version


What

Why

The current handling of implicit definition of and schemas introduces an irregularity into Standard Z which complicates the language definition and implementation. This irregularity is in particular problematic in combination with paragraph reordering (see WG.48.3).

From a methodological point of view, the possibility of attaching non-standard meanings to the phrase can be criticised. If a special meaning of is required, it seems to be better style to document this meaning in a descriptive name for this schema.

How

Updates to the WD 1.5

  • Characters: introduce and as symbols
  • Lexis: introduce and as keywords
  • Concrete and annotated syntax: introduce and as unary operators. Assign them a priority above schema decoration.
  • Transformations: reduce and expressions.

Compatibility
Specifications which make use of the redefinition of can be easily ported by a global textual replace of with e.g. . Specifications which don't make use of the redefinition don't need to be changed - a single lexem followed by a schema name S is the application of the operator to the name S.

Variants

Instead of treating and as symbols, it would be also possible to keep them being letters. Distinguishing between the name and the operation has to be indicated by whitespace, as with decoration. Type checkers will detect that a name (without space) is not defined.
